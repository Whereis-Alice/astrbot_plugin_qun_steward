# 群务管家 · astrbot_plugin_qun_steward

一站式 QQ 群管理 + 群相册插件，为 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 打造。
群内一句指令搞定日常群务，网页面板看清全局，每一步操作都有记录、可撤销。

## 这个插件能做什么

把「群管理」和「群相册」两件事合到一起，并补上原本缺的三块：**看得见（WebUI）**、**查得到（操作日志）**、**改得回（撤销）**。

| 能力 | 说明 |
| --- | --- |
| 成员管理 | 禁言 / 解禁 / 全员禁言 / 改名片 / 改头衔 / 踢人 / 群拉黑 / 上下管 / 群友清理 |
| 消息治理 | 撤回（单条或批量）、精华消息、违禁词、刷屏检测、投票禁言（默认用贴表情计票） |
| 群务设置 | 群名、群头像、发/删群公告、@全体成员（先查剩余次数）、宵禁定时全员禁言 |
| 进群把关 | 自动审核、白词/黑词、等级门槛、重复申请拉黑、待审队列与序号审批、与协议端对账 |
| 增强欢迎 | 按群欢迎开关、多模板随机/顺序、@新人、昵称/群名/人数/时间占位符、欢迎图片、延迟发送、入群算术验证 |
| 群文件 | 浏览目录、上传、删除、下载直链、移动、改名、容量统计、文件夹删除/改名、按规则整理文件 |
| 群相册 | 上传图片到群相册；浏览/删除云端相册图；关键词随机翻相册（直接读云端）；聊天记录渲染成「我朋友说」怪话长图 |
| 群待办 | 引用消息设为待办；实时查看、完成或取消群待办 |
| 群管理策略 | 设置加群方式、入群问题、群搜索、成员邀请策略、新成员历史可见性 |
| 群情报 | 群信息卡片（等级 / 加群方式 / 管理策略）、龙王与群聊之火榜单、当前禁言名单 |
| AI 声聊 | 让机器人用群 AI 音色把一段文字念出来，可列出并临时切换音色 |
| 可视化面板 | 9 个页面覆盖概览、群配置、默认模板、权限、违禁词、日志、待审、相册、全局设置 |
| 安全兜底 | 全量操作审计、危险操作撤销、批量操作节流、协议端能力自动探测 |
| LLM 工具 | 15 个函数调用工具，让大模型在获得授权后代为执行群管动作（默认关闭） |

## 兼容性

- **AstrBot**：4.24.2 及以上。
- **消息平台**：仅 `aiocqhttp`（QQ）。其他平台不会注册指令，也不会报错。
- **协议端**：自动识别并适配
  - [NapCat](https://napneko.github.io/)
  - [LLOneBot / llbot](https://luckylillia.com/guide/introduction)
  - [SnowLuma](https://github.com/SnowLuma/SnowLuma)

  插件启动后会探测一次协议端类型（读 get_version_info 的 app_name），相册等「非标准接口」会按识别结果选择动作名与参数；探测失败时按 NapCat 兼容路径降级，不影响群管功能。

### 新增高级接口的协议差异

群待办和群管理策略不是 OneBot 11 的基础标准接口，是否可用取决于协议端版本和账号权限。插件会在调用前后做能力判断；**不支持时会明确提示，不会把失败说成成功**。

| 能力 | NapCat（较新版本） | LLOneBot / llbot | SnowLuma |
| --- | --- | --- | --- |
| 群待办 | `get_group_todo_list` 等扩展动作 | 当前版本通常不提供 | 支持扩展动作 |
| 加群方式 / 入群问题 | 支持扩展动作 | 当前版本通常不提供 | 支持 |
| 群搜索、成员邀请、新成员历史 | 支持扩展动作 | 当前版本通常不提供 | 支持 |
| 群文件夹删除 / 改名 | `delete_group_file_folder`（兼容旧别名）/ 扩展改名 | 改名取决于版本，删除取决于实现 | 支持 |
| 批量踢人 | `set_group_kick_members` | `batch_delete_group_member` | `set_group_kick_members` |

即使协议端声明支持，机器人也通常需要群主或管理员权限；QQ 侧权限不足时会返回具体失败原因。`群搜索`还可能受 QQ 客户端/账号状态影响，遇到“不支持”可继续使用其他群管功能。

进群申请查询也存在版本差异：插件优先调用 `get_group_system_msg`；只有该动作不可用时，才依次尝试 `get_group_ignored_notifies` 与 `get_group_ignore_add_request`。其中 `get_group_ignore_add_request` 在部分实现里只是兼容存根或兜底入口，不是首选数据源；最终能否列出申请仍以协议端实际返回为准。

### 群相册的协议端差异

三家协议端都支持群相册，但动作名、参数名、返回字段都不一样，插件已逐一适配：

| 协议端 | 列出相册 | 列出相册内媒体 | 上传图片 | 单图删除 |
| --- | --- | --- | --- | --- |
| NapCat | `get_qun_album_list` | `get_group_album_media_list` | `upload_image_to_qun_album`（`file`） | `del_group_album_media`（`lloc`） |
| LLOneBot / llbot | `get_group_album_list` | `get_group_album_media_list` | `upload_group_album`（`files` 数组，无 `album_name`） | 当前官方清单未确认，插件会提示不支持 |
| SnowLuma | `get_qun_album_list` | `get_group_album_media_list` | `upload_image_to_qun_album`（`file` + `album_name`） | 视版本提供，失败会明确提示 |

- 返回字段命名不统一（llbot 是 album_id / name，SnowLuma 是 id / name），插件内部会抹平成同一结构。
- LLOneBot / llbot 的 `get_group_album_list` 当前只接受 `group_id`；插件不会向它附加分页游标。NapCat / SnowLuma 版本若返回游标，则按 `next_has_more` 继续读取，并检测游标不变来避免死循环。
- 列图接口可能返回嵌套的 `image.lloc` / `image.sloc`、`photo_url`、`default_url` 与 `next_has_more`，插件会优先拿到可用的原图地址，并在明确还有下一页时继续翻页。
- 图片参数各端接受的形式不同（本地路径 / file:// / base64://），插件按该协议端最可能成功的顺序逐个尝试。
- llbot 的上传接口**失败时也返回 status: ok**，真正结果藏在 fail_count / fail_indexes 里；插件会检查这两个字段，不会把失败报成成功。
- 如果配置里写了默认相册名、群里却还没有这个相册，在支持新建的协议端（llbot）上会自动创建后再上传。
- `删相册图` 只删除选中的一张图片/一个视频，不提供“一键删除整本相册”，避免误操作造成不可逆的大范围删除。
- 协议端完全没有相册接口时，相册指令会给出明确提示，其余功能照常。

## 安装

### 方式一：插件市场（推荐）

在 AstrBot 面板的「插件市场」搜索 **群务管家** 安装，依赖会自动处理。

### 方式二：手动安装

```bash
cd AstrBot/data/plugins
git clone https://github.com/Whereis-Alice/astrbot_plugin_qun_steward.git
```

然后在 AstrBot 面板重载插件即可（依赖见 `requirements.txt`，AstrBot 会自动安装）。

> **从原插件迁移**：本插件融合了 `astrbot_plugin_qqadmin` 与 `astrbot_plugin_qun_album`，**指令名完全保持一致**。
> 因此请先卸载这两个原插件，否则同名指令会互相冲突。配置项名称有变化，需在本插件里重新配置一次（或用 WebUI 的「默认模板」批量填）。

## 快速上手

1. 把机器人拉进群，并给它**群管理员**权限（大部分操作是协议端的管理接口，没有管理员会失败）。
2. 在 AstrBot 面板的「插件配置」里把 `超管账号` 配好（AstrBot 全局管理员即本插件的「超管」）。
3. 群里发 `群务帮助`，确认插件已响应。
4. 打开 AstrBot 插件管理页的 **群务管家** 面板，在「默认模板」里一次性配置好所有群的基础策略。
5. 需要个别群特殊对待时，去「群配置」页只改那一个群。

### 群待办

| 指令 | 用法示例 | 默认权限 |
| --- | --- | --- |
| 设群待办 / 设置群待办 | **引用一条群消息**后发送 `设群待办` | 管理员 |
| 群待办 / 群待办列表 | `群待办`（实时查询并给出序号） | 管理员 |
| 完成群待办 | `完成群待办 2` | 管理员 |
| 取消群待办 | `取消群待办 2` | 管理员 |

`设群待办` 不接受一段普通文字作为待办内容，必须引用已经存在的群消息。NapCat / SnowLuma 需要协议端提供 `get_group_todo_list` 等群待办扩展；LLOneBot / llbot 当前通常没有这组接口。`完成群待办` 和 `取消群待办` 的数字是**最近一次实时列表里的展示序号**；插件执行前会重新查询列表，再映射到真实消息 ID，避免列表变化后误操作。

| 指令 | 用法示例 | 默认权限 |
| --- | --- | --- |
| 查看群文件 | `查看群文件`、`查看群文件 资料/课件` | 成员 |
| 上传群文件 | 引用文件发 `上传群文件 资料` | 成员 |
| 删除群文件 | `删除群文件 资料/旧版.zip` | 管理员 |
| 群文件直链 / 群文件链接 | `群文件直链 资料/课件.pdf` | 成员 |
| 群文件容量 / 群文件统计 | `群文件容量`（已用空间、文件数、上限） | 成员 |
| 移动群文件 | `移动群文件 旧版.zip 归档`；目标写 `根目录` 即移出文件夹 | 管理员 |
| 重命名群文件 / 群文件改名 | `重命名群文件 资料/v1.zip 课件v1.zip` | 管理员 |
| 删除群文件夹 / 删除群文件目录 | `删除群文件夹 资料`；非空时再发 `删除群文件夹 确认` | 管理员 |
| 重命名群文件夹 / 群文件夹改名 | `重命名群文件夹 资料 资料-归档` 或 `资料 -> 资料-归档` | 管理员 |
| 整理群文件 / 清理群文件 | `整理群文件` 先出候选清单，确认后发 `整理群文件 确认` 才真删 | 管理员 |

「删除群文件夹」会先读取文件夹内容：空文件夹可直接删除，非空文件夹会显示数量和内容示例，必须在 3 分钟内再次发送确认口令。读取内容失败时插件会拒绝删除，避免把“查不到”误判成“空目录”。

「整理群文件」支持四种筛选规则。默认的「散落」只看根目录；其他规则会连同已归档到一级文件夹里的文件一起扫描：

| 规则 | 写法 | 含义 |
| --- | --- | --- |
| 散落（默认） | `整理群文件` | 根目录里没归进任何文件夹的文件 |
| 过期 | `整理群文件 过期` | 协议端标记为已过期 / 已失效的文件（根目录和一级文件夹） |
| 按天数 | `整理群文件 90天` | 上传超过 90 天的文件（根目录和一级文件夹） |
| 按大小 | `整理群文件 100MB` | 大于 100 MB 的文件（根目录和一级文件夹） |

预览列表最多 50 条，确认口令 3 分钟内有效，超时需重新预览；批量删除按「安全设置 → 批量间隔」节流。默认规则是清理根目录里没有归入任何文件夹的散落文件，也可以按「过期」「N天」「N MB」筛选。只要读取目录失败、缺少 `file_id` 或无法确认条目，插件就会拒绝删除。

## 权限模型

身份从低到高：**成员 < 高等级成员 < 管理员 < 群主 < 超管**。

- **超管**：AstrBot 全局配置里的管理员账号，不受群身份限制。
- **高等级成员**：群等级达到「等级门槛」（`level_threshold`）的普通成员，适合把「群友信息」这类只读能力开放给活跃老群友。
- 每条指令的最低身份都能单独调整：WebUI「权限矩阵」→ 选择身份 → 保存，立即生效。投票的「发起」和「参与」是两项独立权限，默认分别为管理员和成员。
- 插件还会检查**机器人自己**的权限。例如机器人只是普通成员时，禁言指令会直接提示「我不是管理员」，而不是让协议端报一串错误。
- 对成员动手的指令（禁言、踢人等）会比较操作者与目标的身份：**不能对同级或更高身份下手**，管理员之间互踢会被拦下。

## 配置方式：默认模板 + 按群覆写

配置分两层，避免「几十个群要改几十遍」：

1. **默认模板**（AstrBot 插件配置里的 `default` 分区，或 WebUI「默认模板」页）：所有群共用的基础策略。
2. **按群覆写**：只有你明确改过的项目才会写进数据库，其余项目永远跟着默认模板走。改了默认模板，所有未覆写的群自动同步。

三种编辑入口任选：

- 群内发 `群管配置` 导出本群配置文本，改完整段粘回去（也可以带上群号在别的地方改）。
- WebUI「群配置」页逐项编辑，已覆写的字段带「已覆写」标记，一眼看出哪些是特例。
- WebUI「群配置」页底部的文本框，直接粘贴另一个群导出的配置，批量套用。

想让某个群回到「完全跟随默认」，用 `群管重置` 或面板上的「恢复为默认」；`群管重置 all` 清空所有群的特例。

## 操作审计与撤销

- 所有管理动作（含被动触发的违禁词处理、进群审批）都会写入本地 SQLite，记录时间、操作者、目标、详情、成功与否、来源（指令 / 面板 / LLM）。
- 群内 `操作日志 禁言 20` 可以直接查最近 20 条禁言相关记录；面板支持关键词与分页。
- 日志按「保留天数」自动清理（默认 30 天），后台任务每小时跑一次。
- 危险操作会入撤销栈，群内发 `撤销` 即可回滚最近一次（默认 15 分钟内有效），`撤销 列表` 查看还能回滚什么。
  受协议端限制，**群拉黑无法撤销**（OneBot 没有统一的移出黑名单接口），插件会在执行前明确提示。

## 违禁词与刷屏

- 三种匹配方式：**包含匹配**（默认）、**整词匹配**（避免「草莓」误伤「草」）、**正则匹配**（高级用法，写错不会影响其他群）。
- 三种处理动作：**仅撤回**、**撤回并禁言**、**仅提醒**。
- **豁免身份**：默认管理员及以上不触发；**白名单**里的词即使命中也放行。
- 内置敏感词库可按群开关，词库延迟加载，不用就不占内存。
- 刷屏检测按「时间窗口内消息条数」判定，窗口与阈值都可配置。

## 投票禁言

`投票禁言 600 @某人` 发起一场投票，让群友自己决定要不要禁。默认走**贴表情计票**：

1. 机器人发出投票公告后，自己先在这条消息上贴好 👍 和 👎。
2. 群友点一下对应表情就算一票，**不用刷指令**，也不会把群聊顶得乱七八糟；改主意就把表情取消掉，票数会跟着变。
3. 任一方先到阈值立刻结算；没到就等超时，按多数票决定。

可配项在「全局设置 → 投票禁言」：

| 配置 | 说明 |
| --- | --- |
| 计票方式 | `两者都行`（默认，贴表情和 `赞同禁言` 指令都收）、`贴表情`、`发指令` |
| 赞同 / 反对表情 | QQ 表情 ID，默认 76（赞）与 77（踩），想换别的表情填对应 ID 即可 |
| 阈值 / 时长 / 超时 | 多少票结算、禁多久、多少秒后自动收摊 |
| 允许自投 | 被投票的人能不能给自己投票 |

协议端不支持贴表情接口时，插件会自动退回指令计票并在公告里说明，不会出现「贴了没反应」的情况。同一个群同时只允许一场投票。

## 进群审核

开启「进群审核」后，插件接管入群申请：

1. 依次判断黑名单 → QQ 等级 → 申请次数 → 黑词 → 白词 → 未命中策略，能自动决策的直接放行或驳回。
2. 拿不定主意的进入**待审队列**并落库，重启不丢；群里会收到带序号的提示。
3. 管理员发 `待审进群` 查看列表，再发 `批准 3` 或 `驳回 3 广告号` 处理；也可以直接引用那条申请通知。
4. 新人入群后交给「增强欢迎」处理：未开启验证时可自动禁言并发送欢迎；开启验证时先完成算术验证。
5. 每次发 `待审进群`，插件都会先**和协议端对账**：协议端还挂着、本地却没记录的申请自动补录；本地留着、协议端已经没有的（别的管理员在手机上处理过、或者申请过期了）自动标记关闭，不会一直挂在队列里。协议端不支持查询时会照常列出本地队列并附一句提示。

## 增强欢迎

增强欢迎把「进群欢迎」从一句固定文本升级成一套可预览、可审计的新人流程：多模板、图片、延迟、占位符和入群验证都可以按群单独配置。

一个典型配置：

```text
欢迎开关 开
欢迎模板 {at} 欢迎 {nickname} 加入 {group_name}！||今天第 {member_count} 位朋友来了：{nickname}
欢迎模式 随机
欢迎图片 https://example.com/welcome.png
欢迎延迟 3
入群验证 开 180
```

### 模板与占位符

- `欢迎开关` 只控制是否发送欢迎消息，不影响入群验证；关闭后模板、图片和延迟配置都保留。
- 如果大多数群都不需要欢迎，可以在 WebUI「默认模板」把 `欢迎开关` 设为关，然后只在目标群里发送 `欢迎开关 开`，或直接发送一条 `欢迎模板 ...`（写入模板会自动开启该群欢迎）。
- `欢迎模板` 支持多条模板，用 `||` 分隔；不带参数查看当前列表，写 `关` 清空。
- `欢迎模式 随机` 每次随机选一条；`欢迎模式 顺序` 按配置顺序轮播。
- 新版 `welcome_templates` 非空时优先；留空则继续使用旧指令 `进群欢迎` 写入的单条欢迎语，老配置不用迁移。
- 未知占位符会原样保留，不会把 `{something}` 变成空白。

| 占位符 | 渲染结果 |
| --- | --- |
| `{at}` | 真正 @ 新人（AstrBot `At` 组件，不拼 CQ 码） |
| `{nickname}` / `{昵称}` | 新人群名片，取不到时用昵称或 QQ 号 |
| `{user_id}` / `{group_id}` | 新人 QQ 号 / 群号 |
| `{group_name}` / `{群名}` | 群名，取不到时显示群号 |
| `{member_count}` / `{人数}` | 当前群人数 |
| `{join_time}` / `{时间}` | 入群时间（默认北京时间） |

### 图片与延迟

- `欢迎图片` 支持 URL、本地路径和 `file://` 路径，多条用 `||` 分隔，会按顺序追加在欢迎语后。
- 用 `+` 追加、`-序号` 移除；无效图片会跳过并写警告，不影响文字欢迎发出。
- `欢迎延迟` 范围 0~300 秒。延迟期间插件卸载或重载时，未发出的欢迎任务会被取消，不会在重载后突然补发。
- 开启入群验证时，延迟会在验证通过后才开始计时。

### 入群算术验证

`入群验证 开 180` 后，新成员入群会收到一道加减乘算术题：

1. 新人直接在群里回复**纯数字答案**，例如 `5`；像「答案是 5」这种普通聊天不会被误判成作答。
2. 验证期间插件会跳过「进群禁言」，否则新人被禁言后根本无法回答。
3. 答对后插件会尽力解除禁言、写审计日志，再发送欢迎语（或按配置延迟发送）。
4. 超时时间范围 15~3600 秒；`验证次数` 可限制最多答错几次，范围 0~10 次，`0` 表示不限。
5. 超时或答错达到上限时，按 `验证动作` 处理：

| 动作 | 行为 |
| --- | --- |
| `踢出`（默认） | 把新人移出群，不写入黑名单 |
| `踢出并拉黑` | 移出群，并加入本群「进群黑名单」 |
| `仅提醒` | 不自动处理，提醒管理员人工跟进 |

验证通过、失败和超时都会写入操作日志。所有欢迎与验证指令默认管理员可用，并接入同一套权限矩阵。该功能只依赖 `group_increase` 通知、禁言 / 踢人接口和常规群信息接口，NapCat、LLOneBot / llbot、SnowLuma 均可使用；实际能否踢人仍取决于机器人是否具备群管理权限。

配置完成后用 `欢迎测试` 预览当前效果，用 `欢迎配置` 一次查看模板、图片、延迟与验证设置。

## 群相册

- `上传群相册 相册名`：把消息里的图片（也支持引用图片）上传到指定相册；相册名可在配置里按群预设，之后直接发 `up` 即可。
- `上传群相册 相册名 10`：把最近 10 条群聊渲染成「我朋友说」风格的对话长图后上传，自带头像、昵称、头衔与等级。
- `查看群相册`：列出本群所有相册；`查看群相册 日常` 再往里看一层，列出图片序号、名称与上传时间，配合 `删相册图 日常 3` 就能把云端相册里的图删掉。
- **随机翻相册**：在「全局设置 → 群相册 → 随机相册」里给群配置关键词，群友发送关键词就随机抽一张图。**现在默认直接读云端相册**（配置项 `cloud_random`），所以哪怕本地备份是关的、或者图是别人在手机上传的，也照样能抽到；协议端不支持云端列图时会自动退回本地备份目录。
- **上传成功时插件不说话**：QQ 客户端本身就会弹出相册卡片，插件不再多刷一条文字。只有上传失败、或者相册是插件顺手新建的（客户端不提示这件事）才会回一句。
- 可选开启本地备份，上传过的图片同时存一份到插件数据目录（现在只是「多一份留档」，不再是随机图的前提）。
- 字体按「自定义路径 → 系统中文字体 → 插件自带 → 下载 → PIL 默认」五级回退，**默认不联网**；需要时可在配置里开启自动下载。

### 会不会被压缩？能上传原图吗

单图上传会**优先按原始来源字节传递**：插件拿到图片后不主动解码、不重编码、不缩放，只根据文件头判断扩展名，再交给协议端。

但要注意两个边界：插件只能拿到「发送者实际发出的那一份」，QQ 客户端发送前已经压缩的图片无法恢复；图片交给协议端后，QQ 服务端是否长期保留原始分辨率与画质也不由插件控制。因此这里的“原图”表示**插件自身不再二次压缩**，不是对 QQ 最终存储结果的绝对保证。想尽量保留原始质量，请让发送者勾选「原图」发送，或直接以文件形式发送。

另外，`上传群相册 相册名 10` 这种把多条群聊渲染成对话长图的用法，本质是插件自己画出来的新图，会重新编码为 PNG，不属于原图直传。

### Emoji 渲染

「我朋友说」怪话图与回复卡片里的 emoji 由插件自研的零依赖渲染器绘制（`core/emoji_text.py`）：按字符簇切分文本，中文/西文交给普通字体，emoji 交给系统彩色字体，再逐段拼回一行。

彩色字体查找顺序：配置项 `custom_emoji_font_path` → 系统字体（Windows `seguiemj.ttf`、macOS `Apple Color Emoji.ttc`、Linux `NotoColorEmoji.ttf`）。找不到彩色字体时会退化为普通字形，不会报错。

已知限制（取决于 Pillow 是否带 Raqm 复杂文本引擎）：

- 无 Raqm 时，ZWJ 组合 emoji（例如 👨‍👩‍👧）会被拆成多个独立 emoji 显示。
- Windows 自带表情字体不含国旗字形，🇨🇳 之类会显示为浅色的 “CN” 字母对。

> 早期版本用的是 `pilmoji`，它会连带 pin 住老版 `emoji` 库并与 AstrBot 运行时冲突，因此已彻底移除，见下方常见问题。

## 回复卡片

帮助、群信息、群荣誉、群文件容量、成员清单这类稍长的结果都会画成卡片图发出。卡片是插件自己画的（`core/card.py`），配色、圆角与徽标跟 logo、WebUI 面板同一套设计语言，画布高度按内容长短自适应，不会出现下面小半张全是空白的情况。

版式上：卡片头部是渐变标题栏加白色盾形徽标（和 logo 同一条轮廓），正文按小节拆开、每节前面一道渐变竖条，关键数值放在统计格里，占用类数据画成带百分比的渐变进度条，榜单前三名带奖牌序号，页脚是一枚迷你盾加署名。

不想收图，或者环境里画不出图时，改配置 `output.card_style`：

| 取值 | 效果 |
| --- | --- |
| `自绘卡片`（默认） | 插件自绘的卡片图 |
| `AstrBot 模板` | 走框架自带的 Markdown 转图片 |
| `纯文本` | 一律发文字，不生成图片 |

自绘失败会自动降级成框架模板，再失败就发纯文本，不会因为画图出错把结果整条吞掉。卡片图写在 `data/cards`，默认只留最近 40 张 / 10 分钟，用完自动清理。

天生很长的列表（群友清单、群友清理预览、审计日志、禁词表、相册列表）走的是另一个开关 `output.long_list_mode`，默认用**合并转发**发出：不刷屏，还能直接复制文字。协议端不支持合并转发时自动改发长图，再失败才回退纯文本。

## LLM 函数调用

插件提供 15 个函数调用工具（禁言、改名片、头衔、全员禁言、踢人、拉黑、精华、群名、群头像、群公告、群文件等），让大模型在对话中直接完成群务。

出于安全考虑：**默认关闭**（`enable_llm_tools`），开启后仍会走完整权限校验——谁在跟机器人说话，就按谁的身份判定，模型无法越权。

## 常见问题

**为什么指令没反应？**
先确认：机器人所在平台是 aiocqhttp；插件已启用；没有和原插件（`astrbot_plugin_qqadmin` / `astrbot_plugin_qun_album`）同时安装；发指令的人身份够。

**提示「我不是管理员」怎么办？**
把机器人设为群管理员。群主专属能力（改头衔、上下管）必须机器人是群主。

**相册指令报「不支持」？**
协议端没有实现相册接口。请升级到 NapCat 4.8.100 以上，或换用支持该接口的实现。

**群待办或群管理策略提示「当前协议端不支持」？**
这几项属于协议端扩展能力，不是 OneBot 11 基础接口。SnowLuma 和较新的 NapCat 通常可用；LLOneBot / llbot 当前通常没有群待办与策略写入接口。插件会明确提示，其他指令不受影响。

**设置群待办为什么必须引用消息？**
群待办本质上绑定 QQ 的真实消息 ID。请先引用目标消息，再发送 `设群待办`；只发送一段文字无法建立可靠关联。

**删除群文件夹会不会误删？**
空文件夹可以直接删除；非空文件夹会先读取内容并要求在 3 分钟内发送 `删除群文件夹 确认`。如果协议端无法读取目录内容，插件会拒绝删除，不会把“读取失败”当成空目录。

**群搜索开了但别人仍搜不到？**
群搜索受 QQ 账号、群状态和协议端实现共同影响；不同协议端可能只支持群指纹搜索或群号搜索其中一项。插件只能报告协议端返回的状态，不能绕过 QQ 侧限制。

**配置改了不生效？**
面板保存后即时生效，无需重启。如果改的是「默认模板」，注意已经单独覆写过的群不会被覆盖——去「群配置」看看该群是否带「已覆写」标记。

**安装时报 `Conflicting modules: pilmoji`？**
完整报错形如 `module 'emoji.unicode_codes' has no attribute 'get_emoji_unicode_dict'`。这是 v1.0.1 及更早版本 pin 的 `pilmoji` + `emoji==1.7.0` 与 AstrBot 运行时里的 `emoji>=2` 不兼容，AstrBot 的依赖预检会因此拒绝加载整个插件。v1.0.2 已移除这两个依赖、改用自研 emoji 渲染，升级到最新版即可；插件现在只依赖 `aiosqlite` / `apscheduler` / `aiohttp` / `pillow`。

**`声聊` 没反应 / 提示不支持？**
AI 声聊依赖协议端的 `get_ai_characters` 与 `send_group_ai_record` 接口，NapCat 与 SnowLuma 较新版本支持，部分实现（或较老版本）没有。插件探测到不支持时会直接告诉你，不会静默失败。另外音色是**按群拉取**的，换群要重新 `声聊音色` 看一次。

**贴表情投票点了没反应？**
先看公告文案：如果写的是「发 `赞同禁言` / `反对禁言`」，说明协议端不支持贴表情接口，已自动退回指令计票。表情计票靠轮询同步，最长可能有几秒延迟。默认只有管理员能发起投票，但所有群成员都能参与表态；两项权限可在 WebUI 分开调整。

**数据存在哪？**
`data/plugin_data/astrbot_plugin_qun_steward/` 下的 `qun_steward.db`（群配置、审计、待审队列）以及公告图、群文件、相册备份等子目录。卸载插件不会自动删除，可手动清理。

## 相比原插件的改进

- **按群欢迎开关**：支持全局默认关闭、指定群开启；只关欢迎消息，不影响入群验证。
- **配置即启用**：在某个群写 `欢迎模板` 或旧 `进群欢迎` 时，会自动开启该群欢迎。
- **延迟安全**：延迟等待期间关闭欢迎，到期后不会补发旧消息。
- 群管与群相册合为一体，共用权限、审计与数据层，不用装两个插件。
- 新增操作审计、危险操作撤销、待审进群持久化队列（序号审批，重启不丢）。
- 违禁词支持整词 / 正则匹配、白名单与豁免身份、分级处理动作。
- 配置改为「默认模板 + 稀疏覆写」，多群管理不再重复劳动。
- 全新 WebUI，覆盖配置、权限、日志、待审、相册；深浅色与中英文。
- 协议端自动探测（NapCat / LLOneBot / SnowLuma），非标准接口按能力降级。
- 批量操作（清理群友等）加并发节流与上限，避免协议端被打爆或触发风控。
- 修复了一批上游问题：权限键错配、刷屏配置读错字段、纯文字公告发不出、配置重置误删、投票状态内存泄漏、精华与成员列表排版、历史消息扫描量失控等。
- 依赖精简到 4 个常见包，移除会与 AstrBot 运行时冲突的 `pilmoji`/`emoji`，改用自研零依赖 emoji 渲染。
- 代码分层重构：`core/` 基础设施、`features/` 业务、`web/` 面板接口，`main.py` 只做编排；全量类型注解，附单元测试。

v1.1.0 又补了一批：

- **投票禁言改成贴表情计票**，群友点一下表情即算一票，不再靠刷指令。

- **新增群情报**：群信息卡片（群等级 / 加群方式 / 当前管理策略）、龙王与群聊之火榜单、当前禁言名单。

- **群公告可以删**（`删除群公告 序号`），上游只能发不能撤。
- 群友清理预览、审计日志、禁词表等长列表改用**合并转发**发出，不再刷屏。
- 跨端调用统一收敛到 `core/protocol.py`：同一能力按多个候选动作名逐个尝试，「不支持」的结论会缓存，不会每次都重试一遍。

## 开发

```bash
pip install -r requirements.txt
pip install ruff pytest pytest-asyncio

ruff check .            # 代码风格
pytest tests/           # 单元测试
python tools/make_logo.py   # 重新生成 logo
```

目录结构：

```text
core/        配置、数据库、权限、协议适配、审计、撤销、群信息缓存、卡片渲染、绘图原语、字体
features/    各业务模块（禁言、精华、违禁词、进群、欢迎、文件、相册、群情报、声聊…）
web/         WebUI 接口层（service 组织数据，api 暴露路由）
pages/       WebUI 前端（原生 JS，无构建步骤）
tools/       辅助脚本
```

欢迎提 Issue 和 PR。改动业务逻辑请顺手补一个测试。
